建个网站有什么用？能做什么？

不确定做一个网站「有什么用」？看这些最常见的玩法——每一种都能用本教程的流程做出来：

🪪

个人主页 · 作品集

一个链接展示你是谁、做过什么。求职、接单、社交主页，都指向这里。

📄

在线简历

比 PDF 直观，改完即生效；链接放进简历和 LinkedIn 主页，永远没有「旧版本」。

🏪

小生意展示页

烘焙、民宿、摄影约拍：作品图 + 价目 + 联系表单，就是你的线上门面。

📚

教程与经验分享

把你会的东西写成教程，搜索引擎长期帮你带来读者，越写越值钱。

🎉

活动落地页

婚礼邀请、社团招新、活动报名：时间地点流程，一个链接讲清楚。

🔧

在线小工具

换算器、倒计时、抽签器……解决一个小问题，也能服务很多人。

📸

兴趣记录

养花、健身、育儿打卡：自己的地盘自己做主，不担心平台停运。

🌱

个人品牌起点

让全网的内容都指向同一个网址，影响力从「有自己的网站」开始积累。

它们的共同点：以展示内容为主，不需要用户登录、在线支付这类复杂功能——正好是这条免费路线最擅长的。要收款、会员这些进阶需求，等网站跑起来再迭代也不迟。

第 1 步 · 想清楚：做什么网站，给谁用

⏱ 15 分钟 💰 $0 🎯 产出：一句话需求

小白做网站失败的第一原因不是技术，是需求模糊。这 15 分钟会让后面每一步都快一倍。

你要做的事

  1. 填三个空：① 给谁用？② 他们来做什么？③ 最重要的一项功能是什么？
  2. 把答案连成一句话。例：「给朋友看的木工作品集，能翻作品照片、一键发邮件联系我。」
  3. 把其余功能全部砍掉，写进「以后再说」清单。第一版只要核心那一件事。

利弊：先想清楚再做 vs 边做边改

✅ 先想清楚（推荐）

  • 一次提示词就能让 AI 做对 80%
  • 返工少，不折腾，半天能上线
  • 逼你想清楚给谁用——这决定网站成败

⚠️ 边做边改

  • 马上能看到页面，很爽
  • 但 AI 只能猜你的意图，来回改十轮
  • 最终堆满「看起来酷」但没人用的功能

⚠️ 小白常踩的坑

  • 想做「类似 Amazon 的电商网站」——Amazon 的十分之一也是公司级工程。从一页开始。
  • 「谁都能用」等于谁都不好用。写一个你认识的、具体的人。
你现在有一句话需求了。

第 2 步 · 准备三样工具，全程免费起步

⏱ 20 分钟 💰 $0

只需要三样东西。不用装传统开发环境、不用买任何东西。

清单

  1. ① 一个 AI 编程助手：网页对话版（ChatGPT / Claude / Gemini）、AI 编程编辑器（Cursor、ZCode）、终端 Agent（ZCode CLI）都行。本教程用免费额度足够。

利弊：AI 助手选哪种形态

形态优点缺点适合

第 3 步 · 让 AI 生成你的第一个网页

⏱ 30–60 分钟（主要在提意见） 💰 $0 🎯 产出：index.html 文件

神奇的一步：你描述，AI 写代码。关键技巧是只要一个文件——双击就能打开，永远不用「编译」「装依赖」。

你要做的事

  1. 把下面的提示词模板复制给 AI，把「括号里的内容」换成你的。
  2. AI 给出代码后，新建一个文件夹，把代码保存为文件名必须是 index.html（全小写）的文件：Windows 用「记事本」粘贴 → 另存为 → 保存类型选「所有文件」、编码选 UTF-8、文件名填 index.html；Mac 用「文本编辑」粘贴后先按 ⇧⌘T 转成纯文本再保存。装个免费的 VS Code 当记事本用也完全可以。
  3. 不满意就直接提意见：「标题大一点」「主色换成墨绿」「加一个作品图集板块」。AI 改到你满意为止。
帮我做一个「单文件」个人网站，全部代码放在一个 index.html 里（HTML+CSS+JS 都内联，不用任何外部依赖）。

【用途】{把第 1 步那句话需求填这里，越具体越好}
【给谁看】{例如：朋友和潜在客户}
【栏目】{例如：关于我 / 作品展示 / 联系方式}
【风格】{例如：简洁温暖，米色背景，深绿主色}
【硬性要求】
1. 手机上打开也要好看（响应式）
2. 支持亮色和暗色两种主题
3. 文字内容你先按用途帮我写一版占位文案，我之后替换

利弊：为什么是单文件（以及 alternatives）

做法优点缺点
⭐ 单文件 HTML（本教程） 双击就能看，零构建，随处托管，AI 一眼读完整个站改起来准 页面多到十几个后会乱；做不了登录类的应用
React / Vue 工程化 能做大型应用，团队协作标准 要装 Node、要构建、要配置部署，个人站杀鸡用牛刀
WordPress 主题插件成熟，适合天天发文章 要买服务器；升级和安全都得自己操心

⚠️ 小白常踩的坑

  • 文件名必须是 index.html。不要 index.html.txt（Windows 默认隐藏扩展名，注意关掉），不要中文名。
  • 如果 AI 开始建五个文件和 package.json，回复：「全部放进一个文件，不要构建步骤」。
  • 别手动来回粘贴三百行代码，直接传文件或用能读文件的助手。
你的电脑里有一个 index.html 了。

第 4 步 · 本地预览，先看效果再上线

⏱ 10 分钟 💰 $0

上线前先自己当第一批访客。这一步免费，还能避免翻车。

你要做的事

  1. 双击 index.html，浏览器直接打开——这就是 90% 的预览。
  2. 按 F12（Mac：⌘⌥I，或右键 →「检查」），再点面板左上角的手机小图标切到手机宽度看一眼。大部分访客在手机上打开你的网站。
  3. 过一遍检查清单：链接都能点、图片都显示、没有残留的占位文字、错别字。

利弊：双击打开 vs 本地小服务器

✅ 双击直接打开（默认）

  • 零配置，听起来多简单就有多简单
  • 看排版、文字、配色、手机版完全够用

🧪 本地小服务器（进阶可选）

  • 只在页面要加载本地数据文件或用模块时才需要
  • 在该文件夹里跑一条命令（Windows 上把 python3 写成 python），然后访问 localhost:8000
  • 双击一切正常就跳过，不用装任何东西

⚠️ 小白常踩的坑

  • 双击打开时个别功能（读取文件、模块）不生效——是浏览器安全限制，不是网站坏了，部署后正常。
  • 图片几 MB 一张会让网站很慢，先压缩到几百 KB 再用。
电脑和手机宽度下都看得过去了。

第 5 步 · 把代码传上 GitHub

⏱ 20 分钟 💰 $0

GitHub 是免费的代码托管 + 版本历史，相当于「网站专用的网盘」，而且下一步它还能直接运行你的网站。

你要做的事（命令行方式）

  1. 在 github.com 点 New repository，起个英文名（如 my-site），选 Public。
  2. 分清两个东西：GitHub 是存代码的网站，git 是你电脑上的工具（Windows 先到 git-scm.com 下载安装 Git for Windows，一路下一步；macOS 第一次运行会自动提示安装，照做即可）。
  3. 打开终端进入你的文件夹：打开终端（Windows 开始菜单搜「PowerShell」，Mac 搜索「终端」），输入 cd 加一个空格，把文件夹拖进窗口，回车。
  4. 第一次用 git，先执行下面两条（换成你的名字和邮箱，以后不用再管）：
git config --global user.name "你的名字"
git config --global user.email "you@example.com"

然后在同一个窗口依次执行（把「你的用户名」和 my-site 换成你自己的）：

git init
git branch -M main
git add -A
git commit -m "我的网站第一版"
git remote add origin https://github.com/你的用户名/my-site.git
git push -u origin main

push 时弹出浏览器让你登录 GitHub、点 Authorize 是正常的授权流程，点完命令会自动继续。

完全不想碰命令行？Plan B：仓库页面点 uploading an existing file，把 index.html 拖进去，效果一样。以后更新也走这条路：仓库页 Add file → Upload files，拖入改过的同名文件覆盖，写一句说明，点 Commit changes。

利弊：代码放哪

选择优点缺点
⭐ GitHub 免费、有版本历史、离免费托管一步之遥、全球标准 免费版 Pages 要求仓库 Public，代码公开可见
只存本地 最简单 没有备份不能上线，误删就没了

⚠️ 小白常踩的坑

  • Public 仓库任何人可见，不要放密码、密钥、私人信息。
  • 本教程用的是 HTTPS 地址，push 时弹浏览器授权即可。如果你换成了 SSH 地址（git@github.com:…）报 Permission denied，说明密钥没配，换回 HTTPS 地址最省事。
刷新仓库页面，能看到 index.html 了。

第 6 步 · 开启 GitHub Pages，网站正式上线 🎉

⏱ 5 分钟操作 + 最长 10 分钟等待 💰 $0

设置里点几下，GitHub 就用它的全球服务器免费帮你运行网站，自动配好 HTTPS。

你要做的事

  1. 仓库页 → Settings → 左侧 Pages。
  2. Build and deployment 选 Deploy from a branch：Branch 选 main / / (root)，点 Save。
  3. 等 1–10 分钟后刷新，页顶会出现绿色链接 https://你的用户名.github.io/my-site/——点开它，这就是你在互联网上的网站。

利弊：免费静态托管对比

托管商优点缺点
⭐ GitHub Pages 不用再注册账号、配置最少、自动 HTTPS 只能放静态站（跑不了后端程序）
Vercel / Netlify 功能多（表单、函数）、每次提交有预览链接 多管一个账号；免费额度限制
Cloudflare Pages 全球 CDN，免费额度大方 对小白配置略多一步

⚠️ 小白常踩的坑

  • 开了还是 404：检查分支选 main、目录选 / (root)、文件名是 index.html。
  • 如果你的 Settings → Pages 里只看到 GitHub Actions、没有 Deploy from a branch：选 GitHub Actions，用官方 Static HTML 模板一路确认即可，效果一样。
  • 改了没变化：Pages 缓存约 10 分钟，强刷或网址后加 ?v=1。
🎉 你的网站已经在互联网上了。

第 7 步 · 绑定自己的域名（可选但推荐）

⏱ 30–60 分钟（主要是等待） 💰 约 $10 / 年

github.io 地址能用，但自己的域名好记、显专业、跟着你走不绑定平台。这是全流程唯一花钱的步骤，完全可以以后再做。

你要做的事

  1. 在注册商（Cloudflare / Namecheap / Porkbun，见下表）搜一个喜欢的名字，付款即得。
  2. 在域名控制台的 DNS 解析里加记录：裸域名（如 example.com）加 4 条 A 记录，分别指向 185.199.108.153、185.199.109.153、185.199.110.153、185.199.111.153；www 加 1 条 CNAME，记录值填 你的用户名.github.io。
  3. 仓库 Settings → Pages → Custom domain 填入域名保存。GitHub 会在几分钟到一小时内自动签发 HTTPS 证书，勾选 Enforce HTTPS。

利弊：要不要买 & 在哪买

选择优点缺点
继续用免费地址 $0，什么都不用做 难记、不专业、绑定平台
⭐ 自有域名 好记有品牌感；HTTPS 免费；换托管商域名不变 每年约 $10；要学一点 DNS
Cloudflare / Namecheap / Porkbun 成本价、DNS 强大、Porkbun 上手友好 界面英文；付款需要 Visa/万事达卡或 PayPal

⚠️ 小白常踩的坑

  • 绑完域名 https 打不开是正常的——证书签发要几分钟到一小时，别反复重新保存。
  • 解析改动最长 10–30 分钟才全球生效（TTL 决定），等待是流程的一部分。
  • 域名按年付费：记得开自动续费或设个提醒，过期被别人抢注就麻烦了。
自己的域名 + 小锁 🔒 打开你的网站。

第 8 步 · SEO 基建：让搜索引擎找到你

⏱ 30 分钟 💰 $0 📈 效果以周计

没人搜得到的网站等于日记。花 30 分钟做基础 SEO，换长期免费流量。

你要做的事

  1. 让 AI 帮你写「网站主题 + 关键词」的 <title>（30 字内）和 meta description（80 字内），写进 index.html 的 <head>。
  2. 在 index.html 旁边加两个小文件：sitemap.xml（页面清单）和 robots.txt（告诉搜索引擎可以来抓取）。一句话让 AI 生成。
  3. 到 Google Search Console 和 Bing 站长（可从 GSC 一键导入）添加网站、验证所有权、提交 sitemap，再用「网址检查」请求编入索引。

利弊：现在做 SEO vs 不做

✅ 现在做基础

  • 30 分钟一次投入，长期免费流量
  • 新站有约 3 个月沙盒期，早提交早开始计时
  • 标题描述同时决定分享链接的样子

⚠️ 不做 / 以后再说

  • 只靠邮件/私信/帖子里直接发链接的话，确实能等
  • 搜索来源永远是 0，每次都从零开始
  • 进阶 SEO（内容矩阵、外链）可以以后，基础不能省

⚠️ 小白常踩的坑

  • 提交 sitemap 后提示「无法读取」多为新站误报，等 72 小时，别反复重交。
  • 前几个月搜索流量≈0 是沙盒期正常现象，不是失败。
搜索引擎已经知道你的网站存在了。

第 9 步 · 统计、推广与持续迭代

⏱ 20 分钟起步，长期习惯 💰 $0

网站是花园不是雕像。这一步给你一个每周只花几分钟的维护循环。

你要做的事

  1. 装免费统计：Cloudflare Web Analytics，添加站点后把一行脚本贴到 </body> 前。无 Cookie、不用弹同意框。
  2. 把网站发到目标用户在的地方：Reddit、X（Twitter）、Product Hunt、Hacker News（Show HN）、LinkedIn，以及他们聚集的 Discord 社群。写清楚它解决什么问题，附链接，发完守一小时评论区。
  3. 迭代：每次修改 = 改文件 → 三条 git 命令 → 约 1 分钟自动上线。把朋友问过的问题沉淀成网站内容，网站会越来越有用。
git add -A
git commit -m "改了联系方式和两张图"
git push

🛠️ 发帖别配随手截图，做一张像样的推广图：ShareForge 几分钟做出精美的网站推广图，Product Hunt / Reddit / X / LinkedIn 尺寸一键导出——带好图的帖子点击率明显更高。

武器一 · 命名公式——起名是第一个 SEO 决策

名字同时决定仓库名、子域名、title 和 H1——一次起名，四处同时受益或受损。

  1. 公式 = 核心搜索词 + 可品牌化的修饰词。TokenLens、JSON Lens、SSE Inspector都是这个模式：用户搜的是 “json formatter” 这类工具词，关键词进名字，title、H1、域名、品牌词四处同时吃到匹配。
  2. 控制在 2 个词、约 16 字符内。title 按「名字 — 关键词描述」拼，总长超约 60 字符会被搜索结果截断。
  3. 避开两个极端：纯通用词排不过老站，纯品牌词没人搜得到。关键词 + 品牌化修饰词，两头都占。
  4. 定稿前三查：搜一下是否已有同名知名产品（有就换，否则品牌词搜索永远被它压着）、仓库名是否被占、子域名是否被占。

武器二 · 写代码前，先验证依赖

别凭记忆猜 CDN 路径和接口字段。写码前逐个用 curl 验证外部资源，再用真实数据样本跑一遍解析规则——光这一条就能消掉大部分「AI 写的代码跑不通」。

  1. 外部数据三级回退：每日构建的小 JSON → 直连全量接口 → 内置兜底数据。合并时逐字段覆盖（非空才覆盖），不要整条替换——在线数据常见缺字段。
  2. 所有网络请求加超时（AbortController，8–15 秒）；重计算设输入上限，超限自动降级为估算，「精确 / 估算」徽标同步跟着变。
  3. 多语言页面：默认语言的文案直接预填进 HTML（爬虫不执行 JS）。语言优先级：URL 参数 → localStorage → 浏览器语言。
  4. 测试：先起本地服务（python3 -m http.server）再开浏览器测功能，别用 file:// 测；上线后验证要带随机参数，绕过 GitHub Pages 的 10 分钟缓存。

常见问题

我完全不会写代码，真的能做出来吗？
能。这条路线的全部代码由 AI 编程助手生成，你负责说清楚想要什么、按步骤复制粘贴和点几下鼠标。本教程每一步都写明了具体操作和常见坑，遇到问题时把报错原样发给 AI，它通常会直接给出修复。
全程要花多少钱？
可以全程 $0：AI 用免费额度起步，GitHub 和 GitHub Pages 免费，网站以 https://你的用户名.github.io/仓库名/ 访问。唯一可能的花费是可选的自有域名，每年约 $10。
需要买服务器吗？
不需要。静态网站托管在 GitHub Pages 上，访问量由 GitHub 的全球网络承担，个人网站完全够用。以后需要用户注册、支付、数据库等后端能力时，再考虑服务器或云函数。
网站上线后想改文字或图片怎么办？
把需求告诉 AI（或自己改 index.html 对应文字），保存后执行 git add、git commit、git push 三条命令，大约 1 分钟后线上自动更新。这就是这套流程最大的好处：改起来和改文档一样简单。
仓库是 Public 的，所有人都能看到我的代码，有问题吗？
能看到，但个人展示站通常无所谓——网页本身就是公开的，访客本来就能查看源码。真正不能放进去的是密码、密钥、私人信息。实在介意：GitHub Pro 支持私有仓库开 Pages，或换 Cloudflare Pages（免费、支持私有仓库）。
必须按顺序一次做完吗？
不必。第 1–6 步按顺序做（约半天），第 7–9 步相互独立，随时可做。每一步的完成状态会自动保存在你的浏览器里，下次打开继续。
